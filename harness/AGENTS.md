# Codex 控制逻辑（RSI 循环）

本文件是控制逻辑的主协议：主 Agent 按它推进任务，只在需要「补外部信息」或「独立评估」时派子 Agent。
两个子 Agent 的提示词在 `agents/web-research.md` 与 `agents/evaluator.md`。

## 角色

| 角色 | 谁来做 | 职责 |
| --- | --- | --- |
| 主 Agent | 当前会话 | 接需求、找问题、头脑风暴、实现、整合结果、维护记忆 |
| 联网搜索 Agent | 子 Agent | 补全思路与证据：最新方法、官方实现、竞品做法 |
| 评估 Agent | 子 Agent | 空白上下文独立核验：这轮产物能不能收口 |

只有这两个子 Agent。其他能力（计划、终端、写代码、联网、读图）用 Codex 内置工具，不新增角色。

## 主循环

1. **接需求**：把目标、边界、验收标准写进 `doc/tasks/PLAN.md` 与 `doc/tasks/STATE.md`；目标含糊先补齐再动手。
2. **找问题**：先写清当前核心矛盾与最大缺口，再列方案；不要直接开写。
3. **头脑风暴**：至少 3 条本质不同的路线；每条给出可行性理由、最大风险、第一步验证；先验证最便宜的关键假设。
4. **补证据**（需要时）：派联网搜索 Agent；外部信息只能当证据，不能直接当结论。
5. **实现**：主 Agent 直接推进；小步走，每步留下可复现的产物与验证方式。
6. **独立评估**：派评估 Agent（空白上下文）；只给目标、产物路径、验收标准。
7. **迭代**：评估有阻塞 → 带阻塞清单回到第 2 步重新定位；只打局部补丁不算解决。
8. **收口**：满足「可停条件」才停；停前更新三件套并提交。

循环不设固定轮数；继续还是停止，只由「评估结论 + 是否还有更高价值动作」决定。

## 思考纪律

- 先写核心矛盾与约束，再列路线；路线差异要体现在假设、方法或验证方式上。
- 连续两轮只做参数微调、措辞修改这类没有新信息的动作 → 判为原地打转，必须换路线。
- 事实、推断、未验证分开写；不确定的一律标「未验证」，不写进结论。
- 结论必须能回到证据：文件、命令输出、日志、来源链接或可复现实验。

## 记忆（只有三件套）

| 文件 | 放什么 | 规则 |
| --- | --- | --- |
| `doc/tasks/PLAN.md` | 待办与下一步 | 开工先读；做完划掉；能删就删 |
| `doc/tasks/STATE.md` | 当前事实：环境、路径、最好结果、未决问题 | 变化后立即更新 |
| `trace.md` | 操作日志：日期 + 动作 + 原因 | 只追加 |

- 不新增第二套记忆文件；长历史不进记忆，只沉淀可复用结论与当前状态。
- 每轮迭代结束更新三件套；换新会话时先读三件套再开工。

## 子 Agent 派发契约

派发时只给四类信息：目标、已知输入（路径/事实）、当前焦点、输出要求（按角色文件）。

- 评估 Agent 必须空白上下文：不传主 Agent 的推理过程、解释和期望结论。
- 默认只读；不给写权限，除非明确指定允许写的文件。
- 子 Agent 报出的阻塞项必须原文保留，主 Agent 不得弱化、改写或删减。

## 可停条件（全部满足才允许停）

- 验收标准逐条对上，产物真实存在、可复现（路径、命令、结果都核过）。
- 评估 Agent 找不到任何阻塞项、缺口或高价值下一步。
- 产物里没有未验证的数字、引用或结论。
- `PLAN.md`、`STATE.md`、`trace.md` 已更新；改动已提交。

## 卫生与提交

- 每个稳定步骤及时 commit；一次提交只包含本轮相关文件。
- 运行产物、日志、缓存、密钥不进 git。
- 不覆盖别人的改动；不删除来源不明的文件。
